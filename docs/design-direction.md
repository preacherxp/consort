# Consort — model matchmaking

- **Purpose:** describe the task, meet Jev’s candidates, choose a model and effort. No model execution or extra provider calls when browsing.
- **Personality:** warm / human. Ink-plum canvas, cream profile cards, rose accent, generous readable type, lightly romantic copy without obscuring technical facts.
- **Signature:** one quiet model profile, above the input in a single-column flow. Swipe left to pass, right to match; labeled buttons work with keyboard and touch. Keep the match reveal subtle. No decorative portrait panels, oversized stickers, repeated slogans or provider-credit footer. Technical details and history are disclosed on demand.
- **Feeling:** playful confidence, not a leaderboard. Jev is your consort who makes introductions; the final choice is yours.

Keep the existing React web stack, catalog, real Decisions API and inspector. Show returned candidates rather than inventing compatibility percentages. Distinguish Jev’s original recommendation from a model the user picks from the shortlist. The inspector always preserves the original request/response. Copy/export describe the user’s actual match. Respect reduced motion; no gesture-only actions.
